# Operations

Run commands from the deployment checkout, normally `/opt/packpanel`.

```sh
docker compose ps
docker compose logs --tail 100 api worker nginx
bash scripts/smoke-test.sh 127.0.0.1 8080 8081
```

## Updates

`bash scripts/deploy.sh` builds the monorepo while the previous deployment remains available, creates a backup, stops application writes, waits for PostgreSQL, applies schema migrations, starts the new images and checks HTTP endpoints. Keep the previous image IDs/tags and source revision for rollback. A passed health check is not a substitute for validating a downloaded desktop launcher.

The public endpoint subtree must be readable by unprivileged Nginx: directories 755 and published files 644. Objects/uploads remain private. `incoming` is excluded by Nginx; never apply recursive public permissions to all storage.

## Backups

```sh
bash scripts/backup.sh
```

Backups are created under `$DATA_DIR/backups`, with private permissions. API/worker writes are stopped during the snapshot and resumed afterward; static distribution stays available. Archives contain a custom-format PostgreSQL dump, storage (including published releases/manifests), launcher builds, persisted public configuration when present, the environment file and the source revision. Runtime download caches are reproducible and excluded.

Treat archives as sensitive: they contain configuration credentials. The script does not automatically delete old backups. Arrange retention according to available disk space and keep a copy outside the server.

## Restoration and rollback

First select the source revision and Docker images compatible with the backup. Restore only a trusted archive generated by the current backup script:

```sh
bash scripts/restore.sh /srv/packpanel/backups/packpanel_backup_DATE.tar.gz
```

The script requests confirmation because it replaces the database. For an authorized unattended restore, use `--yes`. Application writes remain stopped during restoration; PostgreSQL credentials/database names come from the running container. The archived environment file is for manual credential recovery and is not silently applied to the current deployment.

On failure, inspect the error before restarting applications. After restoration, run migrations for the chosen source version if needed, then HTTP checks and a launcher update/launch check. Keep the archived original images/configuration until validation passes.

## Public configuration

`GET/PUT /api/system/public-config` reads/writes administrator-controlled distribution settings. They persist in `$DATA_DIR/public-config.json`; the worker reloads them periodically. Production defaults to HTTPS for the files domain. An explicit HTTP base URL is intended for LAN validation.

The public distribution port serves static files and excludes `/api`, hidden files and incoming uploads. The panel/API belongs on its separate listener and reverse-proxy domain.
